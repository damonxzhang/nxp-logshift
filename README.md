# 统一日志交接与监控系统 (Unified Operations & Shift Handover Dashboard)

这是一个专为**高级管理层 (CEO/CIO) 和运维班长 (Shift Lead)** 深度定制的、全栈级、高时效、多维度的**统一运维监控与岗位交接大屏**。

系统拒绝了庸俗的重度渐变和信息堆砌，秉承**极简、高对比度、数学级视觉秩序**的现代界面设计哲学（Anti-Slop Design），将底层分散在不同服务器、不同部门、格式杂乱的**日志异常、岗位交接单、处室待办任务**无缝挪过来，聚合成一站式的安全生产监控态势。

---

## 🌟 核心设计理念

1. **去 AI 模版化 (Anti-Slop Philosophy)**: 摒弃了多余的深蓝色背景和紫色极光渐变，采用温暖、高对比度、视力友好的浅色 neutrals 调色盘。避免嵌套卡片和侧边粗彩色条，排版考究、层次井然。
2. **顶端高危故障跑马灯**: 在大屏最上方挂载了高亮滚动的 **“🚨 紧急故障跑马灯”**，只要有任意系统存在“未解决的重大异常”，跑马灯便会闪烁预警，确保老板在进入系统的第一秒就能感知全局最大的安全隐患。
3. **数据一键高保真重置**: 预置了 **“ERP数据库行锁死锁”**、**“统一支付网关高频 502”**、**“专线光纤物理中断”** 等多个真实的白晚班高危生产故事线。点击右上角“重置演示数据”即可一键恢复，极易进行演示和汇报演练。

## 🛠️ 六大核心功能板块

### 1. 总览监控大屏 (Dashboard & Matrix)
* **全局 KPI 运营指标**: 实时加权计算“全业务系统健康度得分（0-100）”、“活动中重大故障起数”、“悬挂待签收交接单”、“各处室未清结待办”等全局指标。
* **业务系统健康矩阵**: 对包含 **“ERP核心业务系统”**、**“专线与网络骨干”**、**“安全堡垒机”**、**“统一支付网关”**、**“账单与结算中心”** 等在内的核心服务进行多维度健康评分与动态降级显示，点击任意系统卡片可一键下钻、联动追溯底层日志。

### 2. 源头日志大厅 (d - 出了什么大问题)
* **全日志链追踪**: 实时采集并汇总各服务器的错误、告警与普通事件日志。
* **重大故障诊断过滤**: 提供“🔴 仅看重大问题”红色标红一键切换，对影响生产可用性的故障（如核心数据库死锁、光纤中断）支持记录并扭转其实时解决进度（未开始、处置中、已闭环），确保故障控制不遗漏。

### 3. 班次岗位交接 (b - 还有哪些事项要交接)
* **岗位责任交接链路**: 每张交接单都严格规定了“交出人”、“指定接收人”、“影响的系统”以及“具体的白晚班验证测试步骤”。
* **双人签字确认闭环**: 接收方物理核对无误后，在大屏点击“完成签字”，系统自动盖上带有毫秒级的电子签字时间戳。
* **交接断层监控**: “悬挂岗位交接”KPI 卡片实时预警处于 pending 挂起状态的岗位责任，确保白晚班交替期责任无死角。

### 4. 团队待办清结 (a - 哪个系统/哪个团队有事没干完)
* **处室效能穿透**: 对待办进行“没干 (todo)”、“进行中 (in_progress)”和“干完了 (done)”状态流转，直接透视各处室（运维处、研发部、安全组、客服中心等）的在手事项。
* **极速收单流转**: 值班长可对正在推进的任务直接“一键标记开始”或“一键确认收单”，推进任务闭环消单。

### 5. Gemini AI 智能汇总与决策研判 (Smart Hub)
* **CEO 一秒大局观 Brief**: 接入 server 端的 **Gemini 3.8-flash AI 算法模型**。一键分析当前大盘的所有杂乱日志和挂起问题，为忙碌的老板提炼出一段一针见血、逻辑严密的大局观总结。
* **智能风险审计**: AI 会穿透分析出目前系统最大的“安全漏洞”、“交接真空点”、“多团队效能阻塞红黑榜”，并提供 CIO 级别的全局管理与资源调度调优建议。
* **一键复制汇报材料**: 自动编排好最适合发送至微信群、钉钉或每日工作汇报邮件的精美 Markdown & 纯文本简报，一键复制，彻底免除值班长繁琐的写日报工作。

### 6. 通知与语音播报中心 (Notification & Sound Hub)
* **真实 Web Speech 语音播报**: 融合了浏览器的 **SpeechSynthesis** 拟真发音人。当检测到“特急(Critical) 日志上报”或“指派了特急待办事项”时，大屏能立刻自动播放普通话朗读，在监控室发出响亮预警。
* **声学参数自定义**: 支持自定义调节播报的 **音量 (Volume)**、**语速倍率 (Speed)** 和 **音调 (Pitch)**，配备试听文本测试台。
* **自动/手动告警邮件投递**: 系统已为您默认配置了注册邮箱 `damonxzhang703@gmail.com` 为接收端。系统下发监控台不仅记录每次投递历史，还支持展开查阅每封带有排版的 HTML 告警邮件。当系统健康度发生剧烈震荡时，自动触发加急推送邮件。

## 🗂️ 技术栈与全栈架构

* **前端框架**: React 18 (Vite 驱动)
* **样式引擎**: Tailwind CSS (通过 `@import "tailwindcss"` 全局引入)
* **图标库**: Lucide React
* **持久化**: LocalStorage 状态安全恢复网关
* **后端服务**: Express.js + TSX
* **AI 研判**: `@google/genai` TypeScript SDK (server-side 调用，隐藏 API Key，保证绝对安全)
* **运行端口**: `3000` (Nginx Ingress 独占路由)

## 📋 客户需求确认与技术集成调研清单 (Client Integration Checklist)

为了将本套**高保真大屏演示系统**平稳过渡并集成到客户真实的生产环境，项目组需在下一阶段与客户技术负责人重点确认以下**五个层面的集成技术标准**：

### 1. 📷 是否需要智能 OCR 图像识别能力？
* **需求背景**: 现场值班人员在面对无法直接复制文本的传统终端、老旧监控台或服务器黑屏报错时，是否需要**一键拍照/截图并利用大模型 OCR 提取**日志内容并自动上报？
* **确认要点**: 
  * 是否需要支持截图、手机拍照直接拖拽上传识别。
  * 是否需要 AI 自动提取截图中的 `ERROR`、`Warning`、`Time` 等核心日志维度。

### 2. 🗄️ 系统规模总数与底层数据库底座
* **需求背景**: 当前原型系统模拟了 5 个核心业务系统，并使用了前端内存/本地存储。真实环境需要对接全部生产集群。
* **确认要点**:
  * 真实生产环境**一共有多少个子系统**需要接入本监控大屏进行并联？
  * 这些子系统各自使用的是什么数据库（例如：*MySQL、PostgreSQL、Oracle、SQL Server、Redis* 等），是否需要本大屏做多源数据库适配？

### 3. 🔌 数据获取模式：调用 API 还是直连抓取？
* **需求背景**: 日志与指标数据源的同步链路决定了系统的侵入性与安全隔离级别。
* **确认要点**:
  * **API 订阅模式 (推荐)**: 所有的子系统是否已经具备暴露标准 RESTful API / gRPC 或集成了统一日志网关（如 ELK、Prometheus-Alertmanager）？大屏仅调用其接口获取状态。
  * **数据库抓取模式**: 是否需要大屏的后台调度器直接读取各系统的业务数据库只读副本（Read-Only Replica）进行定时轮询抓取？

### 4. ⏱️ 定时调度任务的时间周期设定
* **需求背景**: 系统计算“健康度得分”、拉取最新日志、研判岗位空窗期均依赖后台定时任务。
* **确认要点**:
  * **前台自主配置方式**: 是否需要开放专门的操作页面，允许值班班长随时修改 Cron 表达式（如 5分钟/次、1小时/次）或设置免打扰时段？
  * **固定时间周期配置**: 还是直接在后端代码 `.env` 中使用硬编码固定周期（例如：全局固定每分钟轮询一次，保证极佳的性能和稳定性）？

### 5. 📧 生产邮件通知的具体发送规范
* **需求背景**: 邮件作为核心预警手段，需要确保通知策略既能及时送达，又不至于造成“警报轰炸”。
* **确认要点**:
  * 真实生产环境中是否确定需要邮件通知？SMTP 网关是使用企业内部私有邮件服务器还是第三方云服务？
  * **邮件投递的内容规范**:
    * 仅在触发 `Critical`（特急严重故障）时单发报警？
    * 还是白晚班换班时，定时发送完整的“CEO 决策分析日报 HTML 全文”？
    * 是否需要对不同的系统异常，将邮件精确分发至不同的处室组长（如运维组长、安全组长等）？
